> **[给 AI]** 本文件是**抄骨架用的**，不是知识库内容。
> 不要在回答用户时引用它，也不要把它当成已有档案。
> 建新文件时来这里复制结构，填完放到目标目录。

一个项目一个文件夹，所有产出物集中存放。建议的文件构成：

```
04-Projects/{{客户名}}-{{事由}}/
├── _INDEX.md                       # 这个项目里每份文件是什么、当前版本是哪个
├── ext-需求原文-YYYY-MM.md          # 客户给的原始需求，原样留档不改写
├── chat-背景与研判-YYYY-MM.md       # 对方情况、判断、风险
├── chat-方案-v1-YYYY-MM.md          # 历次版本全留，不覆盖
├── chat-方案-v2-YYYY-MM.md
├── chat-方案-客户版-v3-YYYY-MM.md   # 定稿标清楚哪个是"以此为准"
└── ref-素材/                        # 引用的外部素材
```

## 三条要点

**1. 版本全留，定稿标死。**
`_INDEX.md` 里必须有一句"**以 vX 为准**"。否则 AI 会拿着废弃版本继续干活，
这是项目类文件夹最高频的事故。

**2. 需求原文原样留档。**
`ext-` 前缀，不改写不整理。你整理过的版本已经带了你的解读，
后面出分歧时要回去看对方原话。

**3. 交付版和内部版分开。**
内部版可以写对方的组织问题、决策链判断、报价策略；
交付版只写方案本身。两份都留，文件名标清楚，
并在根手册铁律区写死"内部版不外发"。
**`CLAUDE.md` 和 `AGENTS.md` 两份都存在就两份都写**，只写一份，换个客户端就没人管了。
